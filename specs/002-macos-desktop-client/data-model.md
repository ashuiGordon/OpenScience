# Data Model: Native macOS Desktop Client

## Design Conventions

- Engine records remain authoritative. Desktop entities are immutable projections or explicitly
  mutable drafts; they never rewrite a recorded run.
- Desktop IDs are opaque lowercase UUID strings with a type prefix. Engine IDs are preserved
  byte-for-byte and never regenerated by Swift.
- Timestamps are UTC RFC 3339 values. Formatting for the current locale occurs only in views.
- Paths are normalized file URLs. A path string is not treated as permission, provenance, or proof
  of containment.
- Persisted desktop JSON uses a `schema_version`; unknown newer major versions fail closed.
- Secret values have no Codable desktop type. Only credential presence and Keychain lookup keys may
  cross feature boundaries.
- Retrieved text, Markdown, JSON, URLs, artifact paths, diagnostics, and event messages are
  untrusted input and are bounded before decoding or display.

## AppPreferences

Non-secret preferences stored independently from engine run records.

| Field | Type | Rules |
|-------|------|-------|
| schema_version | integer | `1` for this feature |
| selected_destination | enum | `new_research`, `runs`, `providers`, `settings` |
| appearance | enum | `system`, `light`, `dark`; defaults to `system` |
| default_source_names | list[string] | Unique names only; absence is allowed |
| default_synthesizer_name | string | Defaults to `extractive` |
| default_limits | DesktopRunLimits | Positive/bounded and clamped to engine contract |
| contact_email | string or null | Valid email or null; non-secret metadata |
| development_engine_url | file URL or null | Allowed only in development/direct builds; never a credential |
| include_research_in_support_export | boolean | Defaults to `false`; no implicit enablement |

`AppPreferences` MUST NOT contain a network grant, plan approval, local-root authorization,
credential, process ID, or claim that an old attempt is active.

## DesktopRunLimits

| Field | Type | Default | Validation |
|-------|------|---------|------------|
| max_records | integer | 50 | 1–10,000 |
| max_network_requests | integer | 10 | 0–10,000 |
| timeout_seconds | integer | 300 | 1–86,400 |

The bridge revalidates against the current engine rather than assuming desktop bounds supersede
engine validation.

## ResearchDraft

Mutable input that can be safely restored because it contains no secret or approval.

| Field | Type | Rules |
|-------|------|-------|
| draft_id | string | `draft-<uuid>` |
| question | string | 10–10,000 Unicode scalar values after trimming |
| scope | string or null | Empty becomes null; maximum 10,000 |
| constraints | list[string] | At most 100; each trimmed and non-empty |
| assumptions | list[string] | At most 100; each trimmed and non-empty |
| source_names | list[string] | Unique, currently available source providers |
| synthesizer_name | string | Currently available synthesis provider |
| local_roots | list[LocalRootSelection] | Unique normalized paths; attempt-scoped selection |
| limits | DesktopRunLimits | Valid value |
| created_at | timestamp | Immutable |
| updated_at | timestamp | Monotonic per draft |

Validation errors are keyed by field and do not discard valid fields. A draft cannot become a
`PlanReview` until its question, selections, provider compatibility, and limits validate.

## LocalRootSelection

| Field | Type | Rules |
|-------|------|-------|
| selection_id | string | `root-<uuid>` |
| url | file URL | Directory selected through native chooser; standardized but not dereferenced for display |
| display_name | string | Non-authoritative user-facing name |
| selected_at | timestamp | Current attempt selection time |
| available | boolean | Last non-destructive availability check |

No security-scoped bookmark or persistent authorization exists in schema version 1. Resume creates
new selections after the researcher chooses the roots again.

## PlanReview and DesktopPlanStep

`PlanReview` is an immutable projection of `openscience plan --json` plus desktop-only risk display.

| Field | Type | Rules |
|-------|------|-------|
| review_id | string | `review-<uuid>` |
| draft_id | string | Existing `ResearchDraft` |
| request_id | string | Exact engine ID |
| plan_id | string | Exact engine ID |
| plan_file_url | file URL | Within this attempt's private directory; restrictive permissions |
| steps | list[DesktopPlanStep] | Non-empty, finite, engine order preserved |
| selected_capabilities | list[ProviderProfile identity] | Frozen for the review |
| local_roots | list[LocalRootSelection] | Frozen display copy |
| created_at | timestamp | Engine/desktop generation time |
| decision | enum | `pending`, `approved`, `rejected`, `expired` |
| decided_at | timestamp or null | Present only for terminal review decision |

`DesktopPlanStep` contains exact `step_id`, title, purpose, capability, dependency IDs, completion
condition, declared risk, and desktop display status. Approval does not mutate the persisted engine
plan's `pending` statuses.

Review transitions:

```text
pending -> approved
        -> rejected
        -> expired   # draft/provider/engine compatibility changed
approved/rejected/expired -> no transition
```

An approved review is consumed by at most one `ExecutionAttempt`. A resume uses a new review and
approval over the saved plan.

## ProviderProfile

Projection of a provider descriptor/health record returned by local discovery.

| Field | Type | Rules |
|-------|------|-------|
| name | string | Globally unique engine name |
| version | string | Immutable version/revision from engine |
| kind | enum or null | `source`, `synthesis`, `analysis`, `export`, or unavailable/unknown |
| risk | enum or null | Engine risk when descriptor is available |
| available | boolean | Local registry health only |
| health_error | string or null | Redacted and bounded |
| requires_credential | enum | `none`, `openalex`, `crossref`, `model`, `unknown` |

Provider discovery has no network grant and performs no live health request.

## CredentialReference

Metadata only; the secret value never appears in this model.

| Field | Type | Rules |
|-------|------|-------|
| credential_kind | enum | `openalex`, `crossref`, `model` |
| keychain_service | string | Fixed application service identifier |
| keychain_account | string | Fixed provider-specific account key |
| is_present | boolean | Result of protected-store metadata lookup |
| updated_at | timestamp or null | Desktop metadata; not secret value |

Environment mapping is fixed:

| Credential kind | Child environment key |
|-----------------|-----------------------|
| openalex | `OPENSCIENCE_OPENALEX_API_KEY` |
| crossref | `OPENSCIENCE_CROSSREF_API_KEY` |
| model | `OPENSCIENCE_MODEL_API_KEY` |

## NetworkGrant

Ephemeral human authorization. It MUST NOT be serialized to preferences or restored as current.

| Field | Type | Rules |
|-------|------|-------|
| grant_id | string | `grant-<uuid>` |
| attempt_id | string | Exactly one `ExecutionAttempt` |
| provider_names | list[string] | Non-empty network-read selections |
| destination_categories | list[string] | Human-readable provider/API categories |
| local_data_categories | list[string] | Question, evidence, metadata, or `none`; explicit |
| max_network_requests | integer | Matches approved draft/resume limit |
| provider_risks | mapping[string,string] | Frozen descriptor risks |
| granted_at | timestamp | Current confirmation time |
| expires_at | timestamp | No later than attempt termination |

Changing providers, limits, local-data exposure, engine version, or attempting resume invalidates
the grant. Absence means network denied and `--allow-network` is omitted.

## ExecutionAttempt

One supervised engine process and its unique correlation workspace.

| Field | Type | Rules |
|-------|------|-------|
| attempt_id | string | `attempt-<uuid>` |
| mode | enum | `run` or `resume` |
| review_id | string | Newly approved `PlanReview` |
| engine_identity | EngineIdentity | Resolved executable, source, version, compatibility |
| task_workspace_url | file URL | Newly created empty directory for this attempt |
| run_directory_url | file URL or null | Exactly one discovered immediate `run-*` child; for resume, validated input run |
| redacted_invocation | RedactedInvocation | Option names/values excluding all secret environment values |
| network_grant_id | string or null | Current-attempt grant only |
| progress_cursor | ProgressCursor | Cursor for the exact run event file |
| process_identifier | integer or null | In-memory only; never restored as active |
| state | AttemptState | State machine below |
| started_at | timestamp or null | Set at process start |
| ended_at | timestamp or null | Set only at terminal attempt state |
| terminal_result | TerminalResult or null | Exactly one decoded stdout object plus exit code |
| bridge_error | BridgeFailure or null | Typed safe failure |

Attempt state transitions:

```text
drafted -> planning -> reviewing -> approved
approved -> preparing -> launching -> discovering_run -> running
running -> requesting_cancellation -> reconciling
running -> reconciling
discovering_run -> terminated_before_run
launching/discovering_run/running/requesting_cancellation -> bridge_failed
reconciling -> completed | partial | failed | cancelled | integrity_warning
any nonterminal pre-launch state -> abandoned
terminal -> no transition
```

Only one attempt may occupy `preparing` through `reconciling` per app instance. `process_identifier`
from a prior app session is discarded; persisted artifacts determine recovery.

## EngineIdentity

| Field | Type | Rules |
|-------|------|-------|
| executable_url | file URL | Absolute, executable, resolved without a shell |
| source | enum | `bundled_helper`, `development_override`, `repository_environment` |
| engine_version | semantic version | Parsed from local version probe |
| expected_contract_major | integer | `1` for this feature |
| compatibility | enum | `compatible`, `too_old`, `too_new`, `unavailable`, `invalid` |

Resolution order for a packaged build is bundled `Contents/Helpers/openscience` first, followed only
by an explicit development override when that build configuration permits it. An app bundle may be
built without the optional self-contained helper, but run creation remains disabled until a
compatible development engine is configured.

## ProgressCursor and DesktopProgressEvent

`ProgressCursor` fields:

| Field | Type | Rules |
|-------|------|-------|
| event_file_url | file URL or null | `<run_directory>/events.jsonl` only |
| byte_offset | integer | Start of the next unread byte; nonnegative |
| last_sequence | integer or null | Last accepted engine sequence |
| last_event_hash | string or null | Display diagnostic only; whole-run validator is authoritative |
| pending_bytes | bytes | Bounded incomplete final line; in-memory only |
| issue | enum or null | `malformed`, `sequence_gap`, `truncated`, `oversized`, `replaced` |

`DesktopProgressEvent` is a bounded presentation projection containing engine `sequence`,
`event_id`, `type`, timestamp, optional step ID, safe status, safe redacted message, and optional
counts. Unknown event types are retained as `other` with their original type label but cannot trigger
actions or terminal success.

Cursor rules:

1. Consume only newline-terminated UTF-8 JSON objects under the maximum line size.
2. Accept the next expected sequence; ignore an exact already-consumed duplicate.
3. Stop and surface an issue on a gap, conflicting duplicate, malformed object, file replacement, or
   root escape.
4. Keep an incomplete final line only while the writer/process may still append; at terminal
   reconciliation an incomplete line is a validation issue.

## TerminalResult and BridgeFailure

`TerminalResult` records child exit code, one decoded command-specific JSON object, bounded redacted
stderr, stdout byte count, and termination reason. It never records the launch environment.

`BridgeFailure` contains a stable desktop code, safe user message, redacted bounded context, recovery
action, and underlying exit/termination metadata. Codes include:

- `engine.unavailable`, `engine.incompatible`
- `process.launch_failed`, `process.timed_out`, `process.terminated`
- `workspace.no_run`, `workspace.multiple_runs`, `workspace.run_escaped`
- `stdout.empty`, `stdout.multiple_objects`, `stdout.invalid_utf8`, `stdout.invalid_json`,
  `stdout.oversized`
- `event.malformed`, `event.sequence_gap`, `event.replaced`, `event.oversized`
- `terminal.exit_mismatch`, `terminal.state_mismatch`
- `credential.unavailable`, `credential.denied`
- `artifact.invalid`, `artifact.unavailable`

## DesktopRunSummary and ValidationProjection

Rebuildable read-only History projection.

| Field | Type | Rules |
|-------|------|-------|
| run_id | string | Exact engine ID; unique in app-managed workspace |
| run_directory_url | file URL | Descendant of managed runs root; no symlink escape |
| question | string | Redacted only for support export, not normal local UI |
| status | enum | Exact validated engine status |
| created_at | timestamp | Engine record |
| updated_at | timestamp | Last terminal/resume event or artifact update |
| capability_identities | list[string] | Name plus version |
| counts | RunCounts | Sources, evidence, claims, limitations, errors |
| completed_step_ids | list[string] | Valid completed prefix |
| validation | ValidationProjection | Current validation result |
| artifact_fingerprint | string | Rebuild/invalidation key, not research provenance authority |

`ValidationProjection` has `checked_at`, `valid`, bounded errors/warnings with stable codes, and the
engine version used. Invalid summaries remain listable but cannot become resume/export input.

## ReportProjection, ClaimView, EvidenceView, and SourceView

`ReportProjection` owns run ID/status, rendered report location, coverage/search dates, limitations,
and indexed claim/evidence/source views. It is generated only after root containment and artifact
validation.

`ClaimView` preserves exact `claim_id`, text, kind, confidence, limitations, creator identity, and
ordered evidence IDs. A sourced fact with no valid supporting link is a presentation/validation
error, never silently downgraded.

`EvidenceView` preserves exact `evidence_id`, source ID, passage, locator, relevance, stance, license,
content hash, and producing step. Passage text is immutable and inert.

`SourceView` preserves exact source ID, canonical ID, identifiers, title, authors, publication date,
type, license, status, provider observations, retrieval records, content hash, and an optional safe
HTTP(S) landing URL.

Relationships:

```text
DesktopRunSummary 1 -> 1 ReportProjection
ReportProjection 1 -> many ClaimView
ClaimView many -> many EvidenceView (by exact evidence ID)
EvidenceView many -> 1 SourceView (by exact source ID)
SourceView 1 -> many RetrievalRecord
```

No relationship is inferred from matching prose.

## Persistence Ownership

| Data | Owner | Persistence | Secret allowed? |
|------|-------|-------------|-----------------|
| Research request/plan/events/report/manifest/records | Python engine | App-managed run directory | No |
| History index | Desktop app | Application Support, rebuildable | No |
| Non-secret preferences/draft restoration | Desktop app | UserDefaults/Application Support | No |
| Provider credentials | macOS Keychain | Protected local credential store | Yes, only here |
| Network grant and plan approval | Desktop app | Attempt lifetime only | No secret; no restoration as authority |
| Child launch environment | Desktop bridge | Process launch lifetime only | Selected secrets transiently |
| Diagnostics/support bundle | Desktop app | Bounded local opt-in artifact | No secret; research excluded by default |

## Cross-Entity Invariants

1. An `ExecutionAttempt` cannot launch without a compatible `EngineIdentity`, valid `ResearchDraft`
   or resume input, approved `PlanReview`, and exact unique task workspace.
2. `--allow-network` is present if and only if a non-expired `NetworkGrant` for that attempt exists.
3. A provider secret environment entry is present if and only if the selected provider requires it
   and the corresponding `CredentialReference` resolves successfully.
4. Secret values are absent from every Codable/persisted desktop entity and every redacted
   invocation.
5. A new-run workspace contains at most one accepted immediate `run-*` child. Ambiguity fails
   closed; the client never selects the newest candidate.
6. Cancellation after discovery targets only `ExecutionAttempt.run_directory_url`.
7. Terminal UI state is set only after process result, event/run artifacts, and fresh engine
   validation reconcile.
8. Resume creates a new `PlanReview`, `NetworkGrant`, process, and local-root selection while
   retaining the engine's original run directory and event history.
9. History cache deletion cannot delete or change a run. Run mutation outside engine operations
   invalidates its projection.
10. Export requires a fresh valid `ValidationProjection` and uses engine export; the app never
    assembles a research bundle itself.
